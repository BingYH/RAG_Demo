# 展示流程：9 分 15 秒内结束

[英文原版](../run_of_show.md)保持纯英文。以下是独立中文版；界面按钮名称保留英文，方便对照操作。

## 面试前准备

所有命令在 RAG_Demo 根目录执行。除非观众要求中文，默认准备英文展示。安装、编译和依赖下载都应提前完成。

```powershell
# 终端 A：本地 Dashboard
.\.venv\Scripts\python.exe -m streamlit run streamlit_app.py

# 终端 B：可选的实时 ROS 证据预览；保持运行
.\.venv\Scripts\python.exe scripts/ros_replay_bridge.py --scenario joint_tracking_oscillation

# 终端 C：校验素材，并寻找可用的既有英文案例
.\.venv\Scripts\python.exe scripts/prepare_interview_demo.py
```

准备脚本只读取本地文件和检查点，不请求模型或 HTTP、不改变工作流，也不批准工单。清单写入 `data/presentation/session_inventory.json`。把列出的 Thread ID 粘贴到 Dashboard 的 **Open an existing thread**，再点击 **Open thread**。不要把历史运行 JSON 当作新检查点，也不要试图倒退已经恢复过的线程。

提前准备以下浏览器标签页：

| 标签页 | 内容 | 展示方式与来源 |
| --- | --- | --- |
| 1 | engineering_workflow.svg | 工程流程图 |
| 2 | Dashboard：英文振荡报告 | 已验证的历史 Local JSON 案例 |
| 3 | Dashboard：Local JSON 的 Missing load context 预览 | 新的澄清演示，不需要生成报告 |
| 4 | Dashboard：英文负载缺失报告和草稿 | 已验证的历史 WSL ROS 案例，保留原始采集快照 |

| 6 | 预先准备的报告所对应的 LangSmith Trace | 历史记录，需要工作区访问权限 |

如果多个 Dashboard 标签页意外共享了状态，通过 Thread ID 重新打开目标案例，不要仅依赖标签页原先的内容。准备好本地清单。调整浏览器缩放，使两个主要指标和报告可读；收起较长的 JSON 和详情面板。提前测试滚动和标签页切换。

确认保存的 ROS 曲线可以从已校验的本地缓存加载。ROS 快照校验失败时，不用 JSON 曲线替代。如果缺少必要案例，应在排练前通过界面明确准备，再运行清单脚本；脚本不会自动创建收费模型运行。

实时 ROS 预览：选择 **WSL ROS**，点击 **Check and load ROS capture**，确认 601 个采样点、采集/测试标识及来源。载入快照不等于执行模型诊断。采集成功和响应不合格可以同时出现。桥接不可用时，明确说明后采用 Local JSON 和历史运行路线。

## 提问与澄清措辞

可选的现场振荡提问（若以英文界面运行，可使用英文原版中的原始提示词）：

> 分析这次离线单关节 PD 响应。指出不满足的演示要求，比较当前与登记控制配置，区分观测和假设，并提出工程验证建议。请用英文回答。

默认计时路线中，新的负载缺失案例停在澄清位置。解释下面的示例回复，不必提交：

> 演示说明：我不知道工具或负载是否更换。请把缺失的负载和惯量记录保留为未解决的证据缺口。

随后打开已经恢复过的 WSL 案例，明确说明这是**另一次此前执行的运行**，用来展示后续过程。不能说它是刚才新建的 Local JSON 线程的继续。只有时间允许时才恢复新线程；恢复可能调用模型，并会推进该线程当前的中断状态。

## 可选的现场生成

经过排练且需要展示时，启动一次新的英文振荡诊断，运行期间解释架构。可见等待超过 30 秒，就打开准备好的报告，并说明它是历史运行。API 延迟和有界纠正可能超过这个预算。不能把仍在执行的运行说成已经完成，也不能仅凭请求中断或失败就判断额度耗尽。

## 提出复测，不宣称已经修复

1. 核查 Kd 变更记录以及变更是否有意。
2. 核查规程、负载/惯量、采样与配置适用范围。
3. 请负责工程师批准具有可比性的测试计划和配置。
4. 使用新的测试/快照 ID 采集，并重新计算相同指标。
5. 对照要求和基准，保留证据并报告剩余偏差。

演示不执行自动调参或实体复测。不能把独立的基准素材当成故障已经修复的证据。

## 故障与超时的简化路线

- 到 3:35 已落后：展示负载缺失暂停，略过其报告细节。
- 到 6:45 已落后：跳过 Trace 界面，改用架构图解释可观测性。
- LangSmith 无法访问：展示本地节点历史与复核记录，明确它们来自本地。
- 模型或网络服务失败：使用已保存报告和已校验的缓存证据。
- ROS 失败：说明来源，采用明确标注来源的历史路线；应用本身不会静默回退。
- 草稿已经批准：换一份待审批草稿，不把已批准记录当作待审批演示。排练时不要批准用户现有工单。
